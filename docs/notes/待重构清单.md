## 二、P0-1 `ui::SettingsPage` 拆分

**现状证据**
- `client/src/ui/pages/settings_page.cpp`：870 行、37 个成员函数；
- 成员包含 `camera_`、`capture_session_`、`video_sink_`、`preview_start_timer_`、`audio_source_`、`audio_io_`、`mic_timer_`、`mic_testing_`、`video_preview_enabled_`、`preview_generation_`、`video_caps_`；
- 方法覆盖：设备枚举（`refreshVideoDevices` / `refreshAudioDevices`）、分辨率/帧率重建、相机预览启停与延迟释放（`scheduleVideoPreview` / `beginVideoPreviewAsync` / `releasePreviewHardware`）、麦克风测试（`startMicTest` / `onMicTimer`）、录制目录（`refreshRecordDirLabel` 等）、偏好（`loadUiPrefs` / `saveUiPrefs` / `applyUiPrefs`）、配置保存与重置。

**问题**
- 一个页面同时持有 Qt Multimedia 硬件对象与其生命周期，任何设备时序 bug（例如预览与 WebRTC 摄像头枚举冲突）都会和 UI 代码纠缠；
- 无法对“设备目录/预览启停/偏好合并”做单测；
- 870 行让任何小改动都要重新理解整页。

**方案**
拆成 4 个可独立测试的单元，页面只做布局与信号转发：
1. `DeviceCatalog`：枚举 `QMediaDevices`、分辨率/帧率候选、当前选择与持久化（`IPreferences`）；
2. `CameraPreviewService`（QObject）：`QCamera` + `QMediaCaptureSession` + `QVideoSink` + generation + 延迟释放逻辑，只发 `frameReady(QImage)`；
3. `MicTestService`（QObject）：`QAudioSource` + 定时器 + 电平计算，只发 `levelChanged(double)`；
4. `PreferencesSection`：主题 / 起始页 / 录制目录 / 重置，读写 `ClientConfig` 与 `preferences()`。

预计 `settings_page.cpp` 870 → 约 300 行。

**风险**：中。设备时序里有历史坑（延迟 50ms 释放硬件、FFmpeg 与 WebRTC 冲突），拆分时必须原样保留 `deferHardware` / `preview_generation_` 语义。

**验收**：设置页逐项操作（切换设备/分辨率/帧率、开关预览、麦克风测试、改主题、改录制目录、重置）行为不变；`UiPreview` 的 `13-settings-general` 等截图一致；新增 `DeviceCatalog` 单测（可用假枚举数据）。

## 三、P0-2 `MessageHub` / `Connection` 可靠性重构

**现状证据**
- `client/src/protocol/message_hub.cpp:138-142`：`invokeMethod("sendWireData", QueuedConnection)` 后立刻 `emit text_send_finished()` —— 只是投递成功，不代表字节写进 socket；
- `client/src/protocol/connection.cpp:118-121`：未连接时只打日志返回 `false`，返回值无人接收；
- `client/src/protocol/message.cpp`：`push()` 用 `try_lock` 自旋最多 2 秒，超时**静默 return**；队列满 1500 时 `push_bounded` **丢最旧**，对 `CreateMeeting`/`JoinMeeting` 与文本一视同仁；
- `message_hub.cpp:168-187`：`worker->wait(3000)` 失败后仍 `delete worker`（删除运行中的 QThread）；
- `connection.cpp:38-40`：`connectToServer` 用 `BlockingQueuedConnection` + 5 秒嵌套事件循环，签名看不出会阻塞；
- 无 WS ping / 应用层心跳 / 自动重连；断链只能靠下一次收发失败发现。

**方案（分 4 个可独立提交的小步）**
1. **发送回执**：`sendWireData` 返回 `bool`，发送线程经 queued 信号把 `(kind, ok, bytes)` 回传；聊天气泡按结果标记“失败/重试”，`text_send_finished` 改名或改为“发送成功”；
2. **队列分级**：控制包不可丢（等待或返回 `false` 让上层提示），文本可丢但计数 + `warn`；`push` 改普通 `mutex`；
3. **线程收尾**：`wait()` 失败不 `delete`，改 `QThread::finished → deleteLater` 或延迟回收；把 epoch/joiner 状态机抽成独立类并单测；
4. **链路健康**：心跳（WS ping 或 `{"t":"ping"}`）15s 一次，连续 2 次失败判死并统一走 `disconnected`；重连退避 1/2/4s。

**风险**：中高（并发/时序）。每步都要用“开会 → 断网 → 重连 → 发消息”手工验证。

**验收**：拔网线/停服务端后 UI 能在一个心跳周期内提示断线；`CreateMeeting` 在队列压力下不丢；进程退出不崩；`test_message_codec` 仍通过。

## 四、P1-1 `ui::MeetingWindow` 减重

**现状证据**：`client/src/ui/pages/meeting_window.cpp` 1332 行、80 个成员函数、约 77 个成员变量。`MeetingSession` 已把网络/线程/控制器装配抽走，但窗口仍负责：
- 会话状态机（`ui::MeetingState`、`reset_meeting_ui`、`close_meeting_window`）；
- 右侧 tab / 侧栏布局与可见性（`apply_tab_bar_visibility`、`show_side_panel_tab`）；
- 设备菜单构建（`show_audio_device_menu` / `show_video_device_menu` + `QMenu`/`QActionGroup`）；
- 录制推帧判断（`on_preview_frame` / `on_remote_frame` 里比较主画面并 `push_frame`）；
- 启动耗时统计（4 个 `_startup*` 字段 + `mark_startup_first_frame`）；
- 会议信息弹层、聊天发送、时长 chip。

**方案**
抽 4 个小组件，窗口只保留“UI 状态 + 信号转发”：
1. `MeetingDeviceMenu`（3 个菜单 + 设备切换 + 偏好写入）；
2. `StartupMetrics`（4 个字段 + `mark_*` + 查询接口）；
3. `RecordingTap`（把“只录主画面”的判断收敛一处，接收帧 + 主画面 id）；
4. `MeetingInfoPopup`（会议详情面板）。

预计 1332 → 约 800 行。

**风险**：中。改动面大，依赖 UiPreview 的 `05-meeting` / `05b-meeting-chat` 截图做回归。

**验收**：开会、切主画面、开关摄像头/麦克风/共享、录制、聊天、会议详情面板行为不变；截图一致。

## 五、P1-2 窗口缩放不连贯

**现状证据**
- `client/include/ui/foundation/frameless_window.h:176-190`：`mouseMoveEvent` 每次直接 `doResize()`；
- `:565-631` `doResize()` 每次重算 `minimumSizeHint()` 并同步 `setGeometry()`，**无节流/合帧**；
- 移动窗口只调 `move()`（`:186`）→ 所以“移动流畅、缩放发涩”；
- 每次 `setGeometry` 会触发：整窗布局重算 + 每个 `VideoGLWidget` 的 FBO 重建（主画面 1 + 成员卡片 N）+ `NoPartialUpdate` 全幅重绘（`client/src/media/video/video_gl_widget.cpp`）；
- 聊天列表 viewport resize → `ChatController::relayout_messages()` 遍历所有气泡做文本测量（`client/src/features/meeting/chat_controller.cpp:151-178`）；
- `client/src/ui/pages/meeting_window.cpp:502` 对 `listWidget->viewport()` 装了 `eventFilter(this)` 但 `MeetingWindow` 并未重写 `eventFilter` → 死代码。

**方案（按顺序）**
1. 改用原生缩放：`windowHandle()->startSystemResize(Qt::Edges)`，删除逐帧 `setGeometry` 路径（最有效）；
2. 若保留手动实现：mouseMove 只记录目标几何，16ms 定时器合帧 + 按下时缓存 `minimumSizeHint`；
3. 缩放期间降载：暂停向 `MeetingVideo` 推帧；GL 控件在交互缩放期间不 `update()`；
4. `ChatController` 重排节流到 100–150ms 或缩放期间跳过；
5. 删除 meeting_window.cpp:502 的死 `installEventFilter`。

**风险**：中（涉及无边框窗口交互）。**验收**：拖动四边/四角缩放跟手；最大化/还原、光标形状、热区命中不变；截图一致。

## 六、P1-3 `MeetingMediaController` 拆分

**风险**：中低。**验收**：入会出画面/声音、开关摄像头麦克风共享、切换设备、共享与摄像头互斥均正常。
